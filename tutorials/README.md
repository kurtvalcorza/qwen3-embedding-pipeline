## What changed from the inference-only tutorial

The previous notebook (`TASK-INFERENCE`) embedded the four README sentences and reported a `not-measurable` verdict because the repository shipped no metric and a batch of vectors has no ground truth. This notebook keeps the embedding contract as Section 5 (on Banking77 queries and intent documents instead of the README sentences) and adds the adaptation contract around it: a real labelled pair corpus, retrieval recall@k and MRR in the carried `metrics.py` with a random floor and a lexical baseline as reference points, a bounded contrastive fine-tuning of the last decoder layers, before/after retrievals, and an artifact that reloads. The per-batch `evaluation_report` still returns `not-measurable`; `pipe.evaluate` is the labelled corpus-level stage (`measured` / `measured-small-sample`).

## Conformance notes

- **Standalone carrier (ST1–ST8):** the primary path performs no clone, repository install, or repository import. Section 2 embeds the repository's 3 modules verbatim in topological dependency order (each tagged `metadata.dimer.embedded_module`; the only rewrites make `DEFAULT_WEIGHTS_DIR` working-directory-relative and remove internal relative package imports), Section 3 carries the 11-file snapshot manifest inline and asserts it against the module's constants before fetching, and `NOTEBOOK_SOURCE` records the repository, revision and module digests in the exports.
- **Parity (PAR1–PAR4):** `tests/test_notebook_parity.py` and `tools/validate_release_assets.py` fail when the carried modules, the inline manifest, or the inline pins differ from the repository, or when the notebook is not byte-identical to the generator's output.
- **Model acquisition (MOD1–MOD9):** `stage_missing_files(WEIGHTS_DIR, allow_download=True)` fetches only the manifest entries a fresh clone lacks (the git-ignored `model.safetensors`), at the pinned revision; `verify_snapshot` re-hashes every entry; `Qwen3EmbeddingPipeline.from_pretrained(weights_dir=WEIGHTS_DIR)` loads the verified files (`local_files_only=True`, `trust_remote_code=False`); no cell outside the carried modules calls `huggingface_hub`, `transformers`, `safetensors`, `urllib` or the model directly.
- **Data (DAT1–DAT9, ST6):** the default sample is two pinned objects — `train.csv` / `test.csv` of Banking77 (839,073 / 239,961 bytes; SHA-256 `b06e26ac…` / `d12d6e3b…`) from `raw.githubusercontent.com` at the pinned `PolyAI-LDN/task-specific-datasets` commit — each refused on any mismatch before it is parsed, turned into `{id, query, positive}` pairs whose positive is the intent name as words, de-duplicated on the message, and drawn by a seeded balanced shuffle into 616 / 154 / 385 records from the release's own train/test members (`check_split_disjoint` asserts it). The template adds a second *External access* bullet naming the host, the byte counts and the CC BY 4.0 licence.
- **Stages (§4.1):** `fetch_corpus` + `read_corpus` + `build_sample_dataset` / `load_byod_dataset` + `split_dataset` (sample acquisition) → `validate_dataset` + `documents` + `check_split_disjoint` + refusal probes (validation, with three digests) → `validate_inputs` + `pipe.embed` on queries and documents with sanity checks and the frozen top-3 lists (inference contract) → `random_floor` + `pipe.lexical_baseline` + `pipe.evaluate` on the frozen model (floor, baseline and frozen) → `pipe.adapt` (bounded contrastive fine-tuning) → `pipe.evaluate` on validation and test with the comparison (evaluation) → `pipe.embed` after adaptation + `evaluation_report` (inference) → `pipe.save_artifact` → `Qwen3EmbeddingPipeline.from_artifact` with the parity assertion (export and reload).
- **Score semantics (UNC1–UNC4):** the pipeline emits no probability, confidence or score with a vector; cosine is a similarity in [-1, 1], not calibrated and not comparable across the frozen and adapted models; recall@k and MRR are ranking metrics over one labelled set with ties counted against the positive; no acceptance threshold ships.
- **Fresh-test exposure through the workshop (peer review F8, 2026-10-18):** the semantic-search workshop draws 2 test.csv messages per intent with its `SAMPLE_SEED` form field. At the recorded seed 42 none of them is in `qwen3_embedding_colab.ipynb`'s pinned fresh test; at any other seed some are (29–46 of 154 at seeds 0, 1, 7 and 123). Such workshop runs are therefore exploratory looks at this tutorial's fresh test: maintainer runs of the workshop keep `SAMPLE_SEED = 42`, and any other run is recorded in `../docs/release-verification.md` as a fresh-test exposure. The workshop's code and behaviour are unchanged.
- **Baselines and evidence (EVAL6/EVAL10/EVAL11):** the random floor, the lexical baseline and the frozen model are scored on the same queries and 77 documents as the adapted model (the 385-query exposed development test, labelled as such; the 770-query fresh test only under the pre-registered settings, with a paired bootstrap interval of the MRR difference), `n_documents` is asserted equal, `median_rank` is printed beside every mean, and every metric is labelled as one seeded split of one corpus; stops read validation, never a test split; the notebook states that the adapter changes the shared decoder layers, prints each document's cosine to its frozen self, and presents top-3 lists before and after as observations, not evidence.
- **Split integrity (SPL1–SPL8):** the split is seeded, balanced over the 77 intents and query-disjoint (the release's own train/test partition); validation selects the epoch and the test split is used for nothing but the final evaluation and the reload-parity check; the notebook states that queries from one user or session must be split by that grouping.
- **Ceilings (VAL6):** `MAX_BATCH` (64), `MAX_TEXT_TOKENS` (8,192, truncated and flagged at inference), `MAX_TEXT_CHARS` (100,000), `MAX_TRAIN_TOKENS` (64, training-only truncation), the record bounds (8..20,000 per training set; a BYOD dataset needs 12 distinct queries so 8 stay for training after the split), the document-set bounds (2..1,000) and the id pattern are stated in the Prerequisites and printed before the model runs; four dataset refusals and one batch refusal are demonstrated.
- **BYOD (DAT10–DAT19):** `USE_BYOD` defaults to `False` so the sample path never opens an upload dialog; when enabled, user pairs and the caller's `INSTRUCTION` flow through the same validation, seeded query-disjoint split, floor and baseline, frozen scoring, fine-tuning, evaluation, retrieval, export and reload cells. The expected schema and the privacy guidance — an internal query log with its relevance labels is restricted data — are stated in the Prerequisites and in Section 4, and the training split is written to `outputs/qwen3_embedding_train.csv` in that shape.
- `tools/validate_release_assets.py` performs source validation only. It does not satisfy the clean-runtime execution requirement; a release review must confirm that a recorded clean run in `../docs/release-verification.md` matches the notebook revision under review before the status is promoted to `Release-grade`.

## Two-stage semantic-search workshop

`DIMER_Qwen3_Semantic_Search_Reranking_Workshop.ipynb` composes the frozen live embedding and reranking models into one two-stage search system and evaluates the retriever and the composed system separately. It is generated by `tools/build_semantic_search_reranking_workshop.py` from `tools/semantic_search_reranking_workshop_source.py`, following `../docs/semantic-search-reranking-workshop-spec.md`. It does no fine-tuning; `qwen3_embedding_colab.ipynb` and the reranker repository's tutorial remain the adaptation notebooks. It is a NOTEBOOK_SPEC 2.1 Candidate pending clean-runtime evidence.

The guided follow-up adds stage predictions, worked checkpoints and collapsed infrastructure. Its optional activity reuses the isolated K-sweep instead of overwriting the canonical run. BYOD now refuses partial labels, keeps only one Qwen model resident at a time, and exports `byod_results.json` / `byod_rankings.csv` with input digests and provenance. The in-kernel installer still requires a session restart when the host has imported a replaced package; this remains an explicit qualification gap, not an uninterrupted Run-all pass. See the scoped comparative-notebook evidence below the primary tutorial record in `../docs/release-verification.md`.
